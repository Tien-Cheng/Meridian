### A-2: Seed Demo Investigation Mutation
- **Tier:** Panic fallback
- **Est. time:** 20 min
- **Depends on:** A-1
- **Blocks:** A-6
- **Files:** `convex/functions/investigations.ts` (add `seedDemo` internal mutation)
- **Output contract:** An `internalMutation` named `seedDemo` that:
  1. Creates an agent thread via `createThread` from the agent component
  2. Creates an investigation record with status `"completed"`
  3. Inserts all demo findings from A-1 (capturing their generated `_id` values)
  4. Inserts supply routes (into `supplyRoutes` table) referencing the finding IDs
  5. Inserts seller dossiers referencing the finding IDs
  6. Inserts the case file
  7. Returns `{ investigationId, threadId }`
- **Acceptance criteria:**
  - Calling `seedDemo` populates all tables for one complete investigation
  - All findings have valid lat/lng matching their region. Findings include `riskScore`, `riskLevel`, and `riskSignals` arrays.
  - Case file references correct finding IDs in `findingSummaries` with `riskScore`/`riskLevel`/`topRiskSignals`. Case includes `publicHealthRiskAssessment`.
  - Investigation is immediately viewable in the UI after seeding
- **Gotchas:**
  - Must create the thread first to get `threadId` for the investigation
  - Use `ctx.db.insert()` for each record and capture returned `_id` values
  - Dossier `relatedListingIds` must be actual `Id<"findings">` — map from the insert results
  - Consider making this callable from `setup.mjs` for dev convenience
