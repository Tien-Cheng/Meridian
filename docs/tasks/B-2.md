### B-2: Implement searchRegion Action
- **Tier:** 1 (CRITICAL PATH)
- **Est. time:** 45 min
- **Depends on:** B-1
- **Blocks:** B-4, INT-1, INT-2
- **Files:** `convex/functions/investigations.ts` (fill in `searchRegion` handler at ~line 91)
- **Output contract:** The `searchRegion` internalAction handler:
  1. Calls `ctx.runMutation(internal.functions.monitor.initAgent, ...)` to create monitor entry
  2. Calls `callTinyFish()` with marketplace search goal (uses B-1's goal pattern)
  3. Processes SSE stream via `processTinyFishStream()`, which auto-updates monitor status
  4. Parses listings from the TinyFish result
  5. For each listing, calculates `priceDeviation = ((listedPrice - baselinePrice) / baselinePrice) * 100`
  6. Creates `findings` entries via `ctx.runMutation(internal.functions.findings.create, ...)` with:
     - `isSuspicious: true` when deviation < -15%
     - `suspicionReasons` array (e.g., `["Price 27% below baseline"]`)
     - Lat/lng from `getCoordinates(region)` in `convex/lib/geocoding.ts`
  7. Updates monitor to "completed" status
- **Acceptance criteria:**
  - Monitor entry created and transitions: "launching" → "searching" → "completed"
  - At least 1 finding written to DB with correct price deviation
  - Findings flagged as suspicious when deviation exceeds -15% threshold
  - Coordinates resolve correctly for the region name
- **Gotchas:**
  - This is an `internalAction` — can call external APIs (TinyFish) but must use `ctx.runMutation()` for all DB writes
  - `processTinyFishStream()` already handles monitor updates as SSE events arrive — study its implementation
  - If TinyFish returns a string instead of JSON, use `JSON.parse()` with try/catch and fall back to `extractorAgent`
  - Region names must exactly match keys in `REGION_COORDINATES` (case-sensitive: "Germany" not "germany")
  - The `findings.create` mutation needs all required schema fields — double-check against `convex/schema.ts`
  - `discoveredAt` should be `Date.now()`
