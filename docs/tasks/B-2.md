### B-2: Implement searchRegion Action
- **Tier:** 1 (CRITICAL PATH)
- **Est. time:** 45 min
- **Depends on:** B-1
- **Blocks:** B-4, INT-1, INT-2
- **Files:** `convex/functions/investigations.ts` (fill in `searchRegion` handler at ~line 91)
- **Output contract:** The `searchRegion` internalAction handler:
  1. Calls `ctx.runMutation(internal.functions.monitor.initAgent, ...)` to create monitor entry
  2. Calls `callTinyFish()` with marketplace search goal (uses B-1's goal pattern)
  3. Processes SSE stream via `processTinyFishStream()`, which auto-updates monitor status
  4. Parses listings from the TinyFish result
  5. For each listing, calculates `priceDeviation = ((listedPrice - legitimatePrice) / legitimatePrice) * 100`
  6. For each listing, runs risk signal assessment (via GPT-5.4-mini `generateObject` with `RiskSignalAssessmentSchema` or inline heuristic) to compute `riskScore` (0-1), `riskLevel` (low/medium/high/critical), and `riskSignals` array. Risk signals include: price deviation magnitude, pharmacy credential absence, missing prescription requirement, missing batch/expiry info, seller account characteristics.
  7. Creates `findings` entries via `ctx.runMutation(internal.functions.findings.create, ...)` with all required schema fields including `riskScore`, `riskLevel`, `riskSignals`, `legitimatePrice`, and pharma-specific optional fields (`hasPharmacyCredentials`, `prescriptionRequired`, etc.) when data is available from TinyFish extraction.
  8. Lat/lng from `getCoordinates(region)` in `convex/lib/geocoding.ts`
  9. Updates monitor to "completed" status
- **Acceptance criteria:**
  - Monitor entry created and transitions: "launching" → "searching" → "completed"
  - At least 1 finding written to DB with correct price deviation
  - Findings assigned `riskLevel` based on composite `riskScore`. Listings with riskScore > 0.7 should be `"high"` or `"critical"`.
  - Coordinates resolve correctly for the region name
- **Gotchas:**
  - This is an `internalAction` — can call external APIs (TinyFish) but must use `ctx.runMutation()` for all DB writes
  - `processTinyFishStream()` already handles monitor updates as SSE events arrive — study its implementation
  - If TinyFish returns a string instead of JSON, use `JSON.parse()` with try/catch and fall back to `extractorAgent`
  - Region names must exactly match keys in `REGION_COORDINATES` (case-sensitive: "Singapore" not "singapore")
  - The `findings.create` mutation needs all required schema fields including `riskScore`, `riskLevel`, `riskSignals`, and `legitimatePrice`. The old `isSuspicious` and `suspicionReasons` fields no longer exist.
  - `discoveredAt` should be `Date.now()`
  - For Tier 1, a simple heuristic (price deviation > 50% = critical, > 30% = high, > 15% = medium, else low) is acceptable as a fallback if GPT calls are slow. Create basic `riskSignals` from available data (e.g., `{ signal: "extreme_price_deviation", label: "Price 60% below legitimate", weight: 0.9, evidence: "Listed at $360 vs legitimate $900" }`).
