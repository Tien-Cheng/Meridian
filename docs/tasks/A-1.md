### A-1: Hardcoded Demo Data Module
- **Tier:** Panic fallback
- **Est. time:** 30 min
- **Depends on:** S0-2
- **Blocks:** A-2, A-6
- **Files:** New file `convex/lib/demoData.ts`
- **Output contract:** Exports `getDemoFindings()`, `getDemoRoutes()`, `getDemoCase()`, `getDemoDossiers()` returning arrays matching the `findings`, `supplyRoutes`, `cases`, and `sellerDossiers` schema shapes. Covers the Ozempic (semaglutide) demo scenario across 3 marketplaces (Amazon US, Lazada Singapore, Shopee Singapore).
- **Acceptance criteria:**
  - Data matches Convex schema types exactly (validated against `convex/schema.ts`)
  - Includes mix of high-risk/critical (4-5) and low/medium risk (3-4) findings across all 3 marketplaces. Each finding must have `riskScore` (0-1), `riskLevel`, and a populated `riskSignals` array.
  - Coordinates use values from `REGION_COORDINATES` in `convex/lib/constants.ts`
  - Price deviations span -10% to -90% for visual variety on the map (legitimate Ozempic ~USD 900/month; counterfeits as low as USD 90). `legitimatePrice` field used (not `baselinePrice`).
  - At least 1 supply route from China to Singapore (verified, high-risk, concern: "Rx drug shipped internationally without prescription verification"). Uses `supplyRoutes` table with `riskLevel` and `concern` fields.
  - Case file includes `publicHealthRiskAssessment`, `highRiskListings` count, `findingSummaries` with `riskScore`/`riskLevel`/`topRiskSignals`, and 2-3 recommended actions with `targetEntity` (e.g., "Singapore HSA", "Lazada Trust & Safety", "FDA").
- **Gotchas:**
  - `investigationId` must be a placeholder — will be swapped at insert time in A-2
  - Finding `_id` values won't exist yet — `relatedListingIds` in dossiers must reference actual IDs created during seeding
  - Use realistic seller names: "HealthDirect_SG", "Health_Direct_Official", "PharmaDeals_US", "MedSupply_Direct". Two should appear linked (same operator across Lazada and Shopee).
  - Include `listingUrl` values pointing to plausible Amazon.com/Lazada.sg/Shopee.sg product pages for demo credibility. Include pharma-specific fields: `hasPharmacyCredentials`, `prescriptionRequired`, `batchNumberVisible`, `expiryDateVisible`, `sellerVerificationBadge`.
  - Demo findings should include a variety of `riskSignals` entries such as: `no_pharmacy_license`, `no_prescription_check`, `extreme_price_deviation`, `new_seller_account`, `stock_photos`, `ships_from_non_manufacturer_region`, `missing_batch_number`, `missing_expiry_date`.
