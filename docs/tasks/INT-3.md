### INT-3: Demo Rehearsal
- **Tier:** 1
- **Est. time:** 20 min
- **Depends on:** INT-1, C-5
- **Blocks:** none
- **Owner:** ALL builders
- **Scheduled time:** 3:30 PM checkpoint
- **Files:** No changes
- **Output contract:**
  1. Full run-through of the demo (live or pre-baked)
  2. Decision: live demo vs pre-baked vs hybrid
  3. Speaking roles assigned
  4. Screen recording captured as backup
- **Acceptance criteria:**
  - Demo runs under 4 minutes
  - All panels show data: map markers, evidence findings, case file, chat messages, TinyFish monitor
  - No visible console errors, blank panels, or loading spinners stuck
  - Each team member knows their speaking part
  - Backup video recorded in case of network issues during presentation
- **Gotchas:**
  - Network issues at the venue could affect Convex WebSocket connections — test on venue WiFi
  - If venue WiFi is unreliable, prepare mobile hotspot as backup
  - Screen recording tools: QuickTime (macOS), OBS, or browser extension
  - Time the demo precisely — hackathon demos are typically 3-5 minutes, going over is bad
  - If live demo is too slow (>60 sec for first results), switch to hybrid: pre-seed demo data, then show one live TinyFish call alongside
  - Make sure the demo machine is charged and set to "Do Not Disturb"
  - Test that the app looks good on a projector/external display (colors may look different)
  - The "DEMO" button (A-6) is the ultimate safety net — if all else fails, click it and narrate over pre-seeded data
