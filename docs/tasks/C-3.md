### C-3: Implement generateCaseFile Tool
- **Tier:** 1
- **Est. time:** 50 min
- **Depends on:** S0-1 (OpenAI key available)
- **Blocks:** C-4
- **Files:** `convex/tools/generateCaseFile.ts`
- **Output contract:** The tool's `execute` function:
  1. Accepts `evidenceJson` (serialized evidence data) as input
  2. Calls OpenAI GPT-5.4 (full model) via `generateObject` with `CaseGenerationSchema` from `shared/schemas.ts`
  3. Returns a complete case file object: executive summary, `publicHealthRiskAssessment`, finding summaries (with `riskScore`/`riskLevel`/`topRiskSignals`), seller dossier summaries (with `networkRiskLevel`), recommended actions (with `targetEntity`)
- **Acceptance criteria:**
  - Makes OpenAI API call with GPT-5.4 (NOT mini — this needs high-quality reasoning)
  - Returns valid `CaseGeneration` shape
  - Executive summary and `publicHealthRiskAssessment` are 2-4 professional sentences each, suitable for regulatory/legal review. Public health risk assessment should specifically address patient safety implications.
  - Recommended actions are specific with `targetEntity` (e.g., action: "Report counterfeit pharmaceutical listing", targetEntity: "Singapore HSA", detail: "File report on HealthDirect_SG selling semaglutide without pharmacy credentials on Lazada")
- **Gotchas:**
  - **Same architecture decision as C-1:** Tool can't query DB directly. Accept serialized evidence.
  - The prompt must include ALL evidence context: findings with price deviations and risk signals, supply routes, seller dossiers
  - Keep input token count reasonable — summarize findings rather than dumping raw data
  - The prompt should set the tone: "Write as a pharmaceutical safety investigator preparing a regulatory enforcement brief for health authorities. Emphasize public health risk and patient safety."
  - GPT-5.4 may take 10-20 seconds for structured output of this complexity
  - If there are no findings at all, generate a "No violations found — investigation clear" case
  - The `CaseGenerationSchema` in `shared/schemas.ts` must include `publicHealthRiskAssessment`, `riskScore`/`riskLevel`/`topRiskSignals` in finding summaries, `networkRiskLevel` in dossier summaries, and `targetEntity` in recommended actions — verify it matches the `cases` table schema
  - `findingSummaries[].findingId` must be actual finding ID strings — the calling action (C-4) provides these
