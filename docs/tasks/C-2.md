### C-2: Implement clusterSellersAction
- **Tier:** 1
- **Est. time:** 40 min
- **Depends on:** C-1
- **Blocks:** C-7, A-7
- **Files:** `convex/functions/investigations.ts` (fill in `clusterSellersAction` handler at ~line 112)
- **Output contract:** The `clusterSellersAction` internalAction handler:
  1. Queries all findings for the investigation via `ctx.runQuery()`
  2. Formats findings data as JSON string for the clustering tool
  3. Calls GPT-5.4-mini (either via C-1's tool or directly) to get clusters
  4. For each cluster, creates a `sellerDossiers` entry via `ctx.runMutation()`
  5. Updates investigation status to show clustering is happening
- **Acceptance criteria:**
  - Queries findings using the `by_investigation` index
  - Creates `sellerDossiers` entries matching the full schema:
    - `clusterId`, `sellerNames`, `marketplaces`, `regions`, `relatedListingIds`
    - `signals` object with boolean fields including `sharedShippingOrigin`
    - `confidenceScore` (0-1)
    - `networkRiskLevel` (low/medium/high/critical)
    - `activeCountries` with lat/lng from `getCoordinates()`
  - `relatedListingIds` are actual `Id<"findings">` values from the DB
- **Gotchas:**
  - Need to add a `create` internal mutation — either in a new `convex/functions/sellerDossiers.ts` or inline in investigations.ts
  - The GPT output will reference sellers by name, not by finding ID. You must map: for each seller name in a cluster, find all findings with that `sellerName` and collect their `_id` values
  - `activeCountries` should be unique regions from the cluster's findings, each with coordinates from `getCoordinates()`
  - `marketplaces` should be unique marketplaces from the cluster's findings
  - If GPT returns no clusters (e.g., all sellers are unique), skip dossier creation and return early
  - Handle the case where GPT hallucinates seller names not in the data — filter to only names that exist in findings
